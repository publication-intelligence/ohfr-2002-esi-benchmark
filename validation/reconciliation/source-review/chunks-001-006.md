# Source-only comparison: chunks 001–006

This is a bounded comparison of the legacy v3 and native v2 benchmarks, not a full benchmark approval. Forty prose pages and three map pages were inspected. No candidate indexes, results, audits or candidate-derived measures were used. The supplied PDF identity and every input listed in the JSON were hash-verified.

## Recommendation

The tested native groupings often preserve the source’s distinctions effectively. Retain those compact combinations, add the verified legacy access routes and specific task contrasts, and repair the defects below before either lineage supports a successor. These packets do not justify a blanket winner. Counts, dates and incumbency were not selection criteria.

2. Create a page/region ledger: retain body prose, substantive block quotations, chapter headings, substantive captions and any available substantive notes; exclude running heads, folios, note-call markers, source credits and bibliographic furniture. Fix these inclusion choices before counting.
3. Resolve maps explicitly: recommended common text denominator retains substantive captions but excludes cartographic internals, scales, key labels and the Paris-sections gazetteer. 4. Normalize extracted Unicode with NFKC; remove soft hyphens; use a reviewed per-page join ledger for line-break hyphenation so lexical compounds are not silently changed. Keep both raw text hash and normalized retained-text hash privately.
